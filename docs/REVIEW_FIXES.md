# 支付识别与代码审查问题处理

本次对应 2026-10-23 的 `ui/sky` 1.4.1 静态审查报告，改动记录在 [CHANGELOG](../CHANGELOG.md) 的“未发布”。源码修复不代表已发布新安装包。

| 报告问题 | 处理方式 |
| --- | --- |
| 页面静止、输入法收起后没有重试 | 事件后保持 15 秒的有界补扫，支持无包名窗口变化；新事件可延长观察。 |
| 高频动画挤掉成功事件 | 有限事件缓存与成功/拒绝证据分开保存；完整证据可提前触发扫描，普通碎片不会挤掉成功金额。 |
| 前台、窗口与 OCR 结果过时 | 按聚焦窗口身份、支付事件包名、会话代际、当前可读内容及授权校验；同窗导航后旧 OCR 也不能覆盖失败、聊天或金额冲突。 |
| 非付款页截图、逐事件遍历开销 | OCR 只在文字不可读或存在付款线索时参与；逐事件路径不再遍历来源节点树，读取窗口按节奏执行。 |
| 优惠金额与“完成”按钮布局 | 排除有明确辅助标签的优惠、红包、奖励、原价等金额；成功标记与主金额可分行；OCR 支持独立“完成”按钮，仍要求成功与明确金额。无标签的冲突金额继续拒绝猜测。 |
| 悬浮提示被关闭、后台拉起被静默阻止 | 提示按草稿状态保留；按 ID 确认界面已展示，超时明确提示；提供不包含金额的待核对通知入口。通知权限与厂商后台策略仍影响入口可用性。 |
| 旧草稿或测试金额吞掉新付款 | 最多 20 笔持久队列，新付款不覆盖编辑；未展示的测试草稿可让位真实付款。 |
| 展示即消费、进程结束丢草稿 | 展示回执与保存/忽略分开，未完成草稿继续保留；保存使用稳定条目标识避免重复提交。 |
| 同额付款与重复提示 | 保留跨渠道 90 秒去重及已处理页面抑制，已保存的同日同来源同额账单提示核对。缺少可靠交易标识时，无法准确区分所有短时间同额交易。 |
| Release 自动使用开发签名 | Release 必须显式提供本地密钥、别名与密码配置，缺少配置构建失败；继续使用既有发行证书以保持升级兼容。 |
| 本机预览 DNS 重绑定及坏请求 | GET/HEAD/POST 校验 Host/Origin；解析长度、JSON 和字段类型异常返回客户端错误，写入失败回滚。 |
| WebView 文件访问、CSV 公式与新返回 API | 禁用文件访问，继续加载随包资源；导出防护覆盖制表符和回车前缀；Android 13 及以上注册系统返回回调并保留旧系统路径。 |
| 文件选择期间导出进程重建 | 使用限量的私有缓存恢复待导出内容，完成或取消后清理。 |

保留正在编辑的账单是明确行为；新付款排队核对，不用新金额强制替换旧编辑。代码格式整理集中在本次改动的识别与交付链路，避免整库机械格式化掩盖业务差异。

测试结果与复现方法见 [自动记账验证](AUTO_BILL.md) 和 [开发说明](DEVELOPMENT.md)。模拟器合成页面不能替代小米 / HyperOS 真机的真实支付与后台策略验证；喵喵 APK 的加固业务也未被完整还原，不能据此承诺所有设备和页面 100% 成功。
