# 离线自动记账：调查与验证

## 1.4.2：支付页面补扫与核对窗口交付（测试版）

本节对应 2026-10-24 的 1.4.2（版本码 `17`）GitHub prerelease 测试版。本次验证结果列于下表，历史版本的通过记录独立保留；真实手机支付和系统截图兼容性仍需复测，不标记为稳定版。

- 收到支持的支付应用事件后，保持最长 15 秒的补扫窗口；后续有效事件可延长观察时间。窗口暂未就绪、文字不可读或截图暂时失败时，按有限节奏继续读取，避免只尝试一次就漏掉延迟渲染的支付结果。离开支付应用、关闭识别或服务停止后结束当前会话。
- 近期事件文字按窗口分别保存在内存，最多保留 8 份普通片段及 4 份成功/拒绝证据、有效期 1.5 秒；空事件不会抹掉已有有效文字。优先解析当前前台窗口的实时内容，仅在实时内容为空或已有成功标记但缺少金额时补用同一窗口的近期事件。历史成功文字不能覆盖当前可读的失败、聊天或导航页面；各窗口金额冲突时不猜测。
- 当前窗口第一次读取没有文字时，仍允许后续取得的同窗口有效节点参与识别。窗口身份、支付应用和 Activity 会话变化会使旧结果失效；系统、输入法及本应用悬浮提示的事件不直接视为支付应用离开前台。
- 截图和 OCR 回调使用会话标识、前台应用、窗口身份及授权状态校验。结果返回时 Activity 场景或窗口已切换、应用已切换、识别已关闭、屏幕已锁定或会话过期的，丢弃结果。Android 14 及以上优先窗口截图；窗口失效时仅在前台校验仍通过的情况下尝试系统截图，禁止截图的窗口不会被绕过。
- 页面、OCR 与可选支付通知共用最多 20 笔的本地待核对草稿队列，新付款不覆盖队首或正在编辑的内容。不同渠道的同来源同金额使用 90 秒去重；这个金额指纹不能区分短时间内两笔真实的同额付款，仍有漏提示边界。队列满时保留已有草稿并显示失败状态。
- 请求启动 Activity 后先显示“等待核对窗口确认打开”；核对界面按草稿 ID 回传展示回执后标记“核对窗口已打开”，草稿仍保留。保存成功或明确取消后才完成该笔，保存使用固定条目标识防止回执中断重复入账。若 2.5 秒后仍未收到回执，明确提示点击悬浮入口及检查后台弹出权限。展示回执不代表账单已经保存，保存仍需用户确认。

以上是简账根据可确认的场景识别思路独立编写的实现，不是移植喵喵记账的反编译代码，也不代表已经恢复其完整识别算法或重试策略。系统强停、后台清理、权限被撤销、支付应用不提供可读文字或可用截图等情况仍会阻止识别或展示，不能承诺所有设备和支付页面 100% 成功。

## 1.4.0–1.4.1：常驻无感模式（历史记录）

- 无感模式一次开启后持续监听页面，文字读取失败时自动调用内置中文 OCR，无需每笔付款打开开关或点击识别按钮；增加模型预热和前台常驻运行通知。
- Android 11 及以上使用系统截图，Android 14 及以上优先窗口截图。图片和页面原文仅在内存处理，不保存、不上传；非付款页不生成账单，跳过密码节点、锁屏、已知登录验证界面及输入法显示期间的 OCR。
- 为判断是否付款页，支付宝、微信、美团及美团外卖的其他前台页面也可能短暂参与本机 OCR；首次开启会明确说明并征求同意。其他应用仅观察包名切换，不读取页面文字或截图。
- 增加可选支付通知读取；通知、页面与 OCR 共用草稿及 90 秒去重。保留已有草稿和编辑内容，无法判断类别默认一级餐饮，保存仍需用户确认。
- 细分无窗口、无文字、读取异常与空白截图诊断，支持复制不含页面原文的诊断信息；保留可选的已有截图识别入口。
- 构建改用 Gradle 与随包中文 ML Kit 模型；离线三个版本无互联网权限，无需 Google Play 服务下载模型。
- 四张本机私有截图的实际 OCR 金额测试通过；在隔离测试版回放截图回调时，四种页面均自动打开金额正确、默认餐饮的核对窗口，该回放不代表系统截图已通过；原图、商户、银行卡与单号未进入公开仓库或发行包。MuMu 系统截图实测返回黑帧，因此不能据此声称小米真机自动截图链路已兼容；需真机复测。

### 首次设置（只需一次）

1. 打开“设置 → 无感自动记账 → 开启无感自动记账”，阅读截图识别范围并同意。
2. 开启简账系统无障碍服务。升级后如截图能力未刷新，关闭后重新开启一次；不是每次付款重开。
3. 小米 / HyperOS 首次允许后台弹出界面、自启动和后台运行，按需锁定后台。Android 13 及以上建议允许常驻通知。
4. 可选开启通知补充并授予系统通知读取权限。随后可退出简账，付款时自动识别并弹出核对窗口。

系统强停、撤销权限、厂商后台清理、支付应用禁止截图或不提供画面时，无法保证自动弹出；不会绕过禁止截图的窗口。Android 8–10 保留文字识别和选择已有截图 OCR。

1.4.1 另补充了 OCR 前台校验和输入法检测的跳过原因诊断。以上为对应版本的实现与验证记录，不替代 1.4.2 的验证结果。下方旧版“不截图”的描述仅适用于相应历史版本，不适用于已明确授权开启的 1.4.0 及以后自动 OCR 模式。

### 本次补充的原生库观察

标准 DEX 的业务代码虽受加固限制，包内原生库仍提供了部分可核对的静态信息。本次通过本地 ELF 符号、重定位表与字节读取观察到：

- `lib/arm64-v8a/libautoIdentify.so` 包含按包名划分的 Activity 路由配置，使用精确匹配、前缀匹配和正则匹配，并出现 `pageType`、`currPageType`、`varyPageType`、`paySource`、`skipCount` 和 `diffTime` 等字段。微信订单详情、支付宝收银台与小程序使用不同页型；密码、指纹、人脸和部分加载对话框在跳过配置中。因此可以确认存在页面场景与转场配置，不能把某个 Activity 类名直接当成付款完成证据。
- 例如微信 `OrderHandlerUI` 的配置含 `skipCount=1`、`diffTime=200`。字段和值是直接观察；该值在运行时的单位、完整重试顺序及实际效果未验证，不能据此声称原应用采用简账本次的 15 秒补扫策略。
- 同库含金额格式及账单页面结构的正则字符串，涵盖货币符号、千分位、小数，以及交易成功、已支付、支付方式和订单时间等上下文。字符串存在不证明每条规则一定被调用，也未恢复完整字段提取算法。
- `libautoAccessibility.so` 的 JNI 注册表可对应到类名 `com/mlethe/library/accessibility/auto/AccessibilityNative`，暴露页面分类与数据处理接口；候选识别库 `libautoIdentify.so` 提供同名导出。结合库名、动态链接导入及同名接口，可推断两库之间存在包装关系，但未反编译方法体，完整调用关系仍未确认。

## 简账 1.3.2 的问题及 1.3.3 调整

| 原流程问题 | 调整 |
| --- | --- |
| 每次页面变化都重置扫描延迟，连续动画可能使扫描一直等不到执行 | 限定节奏扫描，不因新事件无限推迟；增加有限的延迟重试 |
| 仅读取活动窗口的文字 | 读取同一支付应用的事件来源、活动窗口和交互窗口，包含内容描述，跳过密码节点 |
| 页面包含多个金额或出现“申请退款”等文字就容易漏识别 | 实付金额优先于优惠、原价；识别完整支付成功上下文；有歧义时继续拒绝猜测 |
| 只有悬浮提示，点击后才进入主界面 | 草稿准备好后尝试自动打开核对窗口；保留可点击悬浮提示作为后备 |
| 依靠定时器获取并立即清除草稿 | Activity 恢复和新 Intent 主动投递，只有前台且没有编辑中弹窗时才展示；展示成功后确认消费 |
| 识别或显示失败没有状态 | 区分应用开关、系统授权、服务连接、页面事件、文字读取、金额识别和待打开核对窗口 |

仅处理本地页面文字，不截图、不上传页面内容、不执行付款操作、不自动保存账单。诊断只保存阶段状态与时间，不保存原始支付页面文字。未处理草稿不会被新识别覆盖。

## 1.3.4 支持的支付文字布局

- 针对支付宝成功页、微信商户成功页、美团支付成功弹层、微信支出账单详情增加文字布局规则；区分主支付金额和下方优惠、奖励、商品价格。
- 微信支出详情支持负号金额；仍排除退款、转账、收款、支付失败及不明确的多金额。
- 增加美团与美团外卖监听，补读页面事件本身的文字和内容描述；各窗口独立解析，避免混合不同窗口内容。
- 自动识别草稿无法判断类别时默认选择一级“餐饮”，用户核对时可修改；若已删除餐饮，使用现有支出分类，避免修改用户分类设置。
- 设置中明确展示“最近识别状态”。仍需用户核对后保存，不自动写入账本。
- 四种布局使用虚构商户和交易信息通过 Java 测试及 MuMu 端到端核对窗口测试，原始截图、真实商户、银行卡和交易单号不进入仓库。文字规则通过不代表小米真机全部兼容；系统不提供任何文字时仍无法识别，本版不含截图 OCR。

## 真机排查（适用于当前工作区实现）

1. 设置中同时检查“应用内识别已开”“无障碍服务已连接”。只开系统无障碍不代表应用内开关已开启。
2. 点击“测试记账窗口”，3 秒后应出现 12.34 元虚构草稿。可先退到桌面测试；不要将测试草稿保存为真实账单。此测试只验证弹窗链路。
3. 小米 / HyperOS 如果测试不能后台弹出，在系统应用设置中检查后台弹出界面、自启动和后台运行限制；具体名称随系统版本变化。简账不会替用户修改这些权限。
4. 若测试可用但真实付款不触发，查看最近识别阶段：没有事件、前台窗口未就绪、没有可读文字、缺少成功标记、多金额不明确、截图/OCR 跳过原因、队列满或等待展示回执，分别对应不同环节。
5. 开启自动 OCR 后，文字不可读会在授权范围内尝试本地截图识别；系统返回黑帧、窗口禁止截图或 OCR 仍无法确认金额时，不会凭空生成账单。仍需真机复测才能确认具体支付应用与系统版本的兼容性。

Android 限制后台 Activity 启动，厂商还可能施加额外策略。参考 [Android 后台界面启动说明](https://developer.android.com/guide/components/activities/secure-bal) 和 [无障碍服务 API](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)。
