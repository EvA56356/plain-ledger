# 离线自动记账：调查与验证

## 当前版本：常驻无感模式

- 无感模式一次开启后持续监听页面，文字读取失败时自动调用内置中文 OCR，无需每笔付款打开开关或点击识别按钮；增加模型预热和前台常驻运行通知。
- Android 11 及以上使用系统截图，Android 14 及以上优先窗口截图。图片和页面原文仅在内存处理，不保存、不上传；非付款页不生成账单，跳过密码节点、锁屏、已知登录验证界面及输入法显示期间的 OCR。
- 为判断是否付款页，支付宝、微信、美团及美团外卖的其他前台页面也可能短暂参与本机 OCR；首次开启会明确说明并征求同意。其他应用仅观察包名切换，不读取页面文字或截图。
- 增加可选支付通知读取；通知、页面与 OCR 共用草稿及 90 秒去重。保留已有草稿和编辑内容，无法判断类别默认一级餐饮，保存仍需用户确认。
- 细分无窗口、无文字、读取异常与空白截图诊断，支持复制不含页面原文的诊断信息；保留可选的已有截图识别入口。
- 构建改用 Gradle 与随包中文 ML Kit 模型；离线三个版本无互联网权限，无需 Google Play 服务下载模型。
- 四张本机私有截图的实际 OCR 金额测试通过；在隔离测试版回放截图回调时，四种页面均自动打开金额正确、默认餐饮的核对窗口，该回放不代表系统截图已通过；原图、商户、银行卡与单号未进入公开仓库或发行包。MuMu 系统截图实测返回黑帧，因此不能据此声称小米真机自动截图链路已兼容；需真机复测。

### 首次设置（只需一次）

1. 打开“设置 → 无感自动记账 → 开启无感自动记账”，阅读截图识别范围并同意。
2. 开启简账系统无障碍服务。升级后如截图能力未刷新，关闭后重新开启一次；不是每次付款重开。
3. 小米 / HyperOS 首次允许后台弹出界面、自启动和后台运行，按需锁定后台。Android 13 及以上建议允许常驻通知。
4. 可选开启通知补充并授予系统通知读取权限。随后可退出简账，付款时自动识别并弹出核对窗口。

系统强停、撤销权限、厂商后台清理、支付应用禁止截图或不提供画面时，无法保证自动弹出；不会绕过禁止截图的窗口。Android 8–10 保留文字识别和选择已有截图 OCR。

以下为历史版本调查与实现记录，旧版“不截图”的描述不适用于已明确授权开启的 1.4.0 自动 OCR 模式。

## 简账 1.3.2 的问题及 1.3.3 调整

| 原流程问题 | 调整 |
| --- | --- |
| 每次页面变化都重置扫描延迟，连续动画可能使扫描一直等不到执行 | 限定节奏扫描，不因新事件无限推迟；增加有限的延迟重试 |
| 仅读取活动窗口的文字 | 读取同一支付应用的事件来源、活动窗口和交互窗口，包含内容描述，跳过密码节点 |
| 页面包含多个金额或出现“申请退款”等文字就容易漏识别 | 实付金额优先于优惠、原价；识别完整支付成功上下文；有歧义时继续拒绝猜测 |
| 只有悬浮提示，点击后才进入主界面 | 草稿准备好后尝试自动打开核对窗口；保留可点击悬浮提示作为后备 |
| 依靠定时器获取并立即清除草稿 | Activity 恢复和新 Intent 主动投递，只有前台且没有编辑中弹窗时才展示；展示成功后确认消费 |
| 识别或显示失败没有状态 | 区分应用开关、系统授权、服务连接、页面事件、文字读取、金额识别和待打开核对窗口 |

仅处理本地页面文字，不截图、不上传页面内容、不执行付款操作、不自动保存账单。诊断只保存阶段状态与时间，不保存原始支付页面文字。未处理草稿不会被新识别覆盖。

## 1.3.4 支持的支付文字布局

- 针对支付宝成功页、微信商户成功页、美团支付成功弹层、微信支出账单详情增加文字布局规则；区分主支付金额和下方优惠、奖励、商品价格。
- 微信支出详情支持负号金额；仍排除退款、转账、收款、支付失败及不明确的多金额。
- 增加美团与美团外卖监听，补读页面事件本身的文字和内容描述；各窗口独立解析，避免混合不同窗口内容。
- 自动识别草稿无法判断类别时默认选择一级“餐饮”，用户核对时可修改；若已删除餐饮，使用现有支出分类，避免修改用户分类设置。
- 设置中明确展示“最近识别状态”。仍需用户核对后保存，不自动写入账本。
- 四种布局使用虚构商户和交易信息通过 Java 测试及 MuMu 端到端核对窗口测试，原始截图、真实商户、银行卡和交易单号不进入仓库。文字规则通过不代表小米真机全部兼容；系统不提供任何文字时仍无法识别，本版不含截图 OCR。

## 真机排查

1. 设置中同时检查“应用内识别已开”“无障碍服务已连接”。只开系统无障碍不代表应用内开关已开启。
2. 点击“测试记账窗口”，3 秒后应出现 12.34 元虚构草稿。可先退到桌面测试；不要将测试草稿保存为真实账单。此测试只验证弹窗链路。
3. 小米 / HyperOS 如果测试不能后台弹出，在系统应用设置中检查后台弹出界面、自启动和后台运行限制；具体名称随系统版本变化。简账不会替用户修改这些权限。
4. 若测试可用但真实付款不触发，查看最近识别阶段：没有事件、没有可读文字、缺少成功标记、多金额不明确或重复账单，分别对应不同环节。
5. 支付页面不暴露可读内容时，此版本不会绕过系统限制或凭空猜测金额。仍需真机页面证据才能继续适配。

Android 限制后台 Activity 启动，厂商还可能施加额外策略。参考 [Android 后台界面启动说明](https://developer.android.com/guide/components/activities/secure-bal) 和 [无障碍服务 API](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)。

## 验证范围

- Java 金额识别测试：付款成功、实付优先、金额与货币符号分离、全角数字、无标签小数、退款/转账排除及歧义拒绝。
- 网页桥接测试：草稿前台投递、正在编辑时保留、展示后确认消费、测试草稿不自动保存。
- MuMu：从桌面自动拉起核对窗口；在隔离测试构建中使用独立且明确标注虚构的页面，验证内容描述金额、连续页面更新及原价/实付区分，成功打开核对窗口。测试构建和测试器未发布，当时正式 APK 只监听支付宝和微信；1.3.4 增加美团与美团外卖。
- 尚未在小米真机或真实支付宝交易上复测，不能将模拟验证当作所有真机已兼容。
