## 简账 1.3.2 的问题及 1.3.3 调整

| 原流程问题 | 调整 |
| --- | --- |
| 每次页面变化都重置扫描延迟，连续动画可能使扫描一直等不到执行 | 限定节奏扫描，不因新事件无限推迟；增加有限的延迟重试 |
| 仅读取活动窗口的文字 | 读取同一支付应用的事件来源、活动窗口和交互窗口，包含内容描述，跳过密码节点 |
| 页面包含多个金额或出现“申请退款”等文字就容易漏识别 | 实付金额优先于优惠、原价；识别完整支付成功上下文；有歧义时继续拒绝猜测 |
| 只有悬浮提示，点击后才进入主界面 | 草稿准备好后尝试自动打开核对窗口；保留可点击悬浮提示作为后备 |
| 依靠定时器获取并立即清除草稿 | Activity 恢复和新 Intent 主动投递，只有前台且没有编辑中弹窗时才展示；展示成功后确认消费 |
| 识别或显示失败没有状态 | 区分应用开关、系统授权、服务连接、页面事件、文字读取、金额识别和待打开核对窗口 |

仅处理本地页面文字，不截图、不上传页面内容、不执行付款操作、不自动保存账单。诊断只保存阶段状态与时间，不保存原始支付页面文字。未处理草稿不会被新识别覆盖。

## 真机排查

1. 设置中同时检查“应用内识别已开”“无障碍服务已连接”。只开系统无障碍不代表应用内开关已开启。
2. 点击“测试记账窗口”，3 秒后应出现 12.34 元虚构草稿。可先退到桌面测试；不要将测试草稿保存为真实账单。此测试只验证弹窗链路。
3. 小米 / HyperOS 如果测试不能后台弹出，在系统应用设置中检查后台弹出界面、自启动和后台运行限制；具体名称随系统版本变化。简账不会替用户修改这些权限。
4. 若测试可用但真实付款不触发，查看最近识别阶段：没有事件、没有可读文字、缺少成功标记、多金额不明确或重复账单，分别对应不同环节。
5. 支付页面不暴露可读内容时，此版本不会绕过系统限制或凭空猜测金额。仍需真机页面证据才能继续适配。

Android 限制后台 Activity 启动，厂商还可能施加额外策略。参考 [Android 后台界面启动说明](https://developer.android.com/guide/components/activities/secure-bal) 和 [无障碍服务 API](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)。

## 验证范围

- Java 金额识别测试：付款成功、实付优先、金额与货币符号分离、全角数字、无标签小数、退款/转账排除及歧义拒绝。
- 网页桥接测试：草稿前台投递、正在编辑时保留、展示后确认消费、测试草稿不自动保存。
- MuMu：从桌面自动拉起核对窗口；在隔离测试构建中使用独立且明确标注虚构的页面，验证内容描述金额、连续页面更新及原价/实付区分，成功打开核对窗口。测试构建和测试器未发布，正式 APK 只监听支付宝和微信。
- 尚未在小米真机或真实支付宝交易上复测，不能将模拟验证当作所有真机已兼容。
